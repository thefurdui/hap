# v1.2.0 implementation record

Each numbered audit finding is implemented in its own conventional commit, with regression coverage where behavior changes. The release includes all 32 findings. Remote publication and tagging are separate from this local implementation.

1. Validate names and filesystem boundaries; reject workspace/profile traversal and symlinked workspace roots.
2. Refuse symlinks and existing files in shared-state destinations, including Git metadata paths.
3. Retain local branches, preserve detached tips under recovery refs, and lease remote deletion against verified local history.
4. Apply the dirty-worktree guard regardless of remote deletion flags.
5. Inventory all workspace contents, verify worktree ownership, preserve ignored files and Git locks, and remove only through Git plus empty-directory removal.
6. Use literal, unformatted session identities and registered project aliases; preserve workspaces when activity is unknown.
7. Protect main, active/resumable workspaces, standard long-lived branches, origin's default branch, and additional hap.protectedBranch Git settings.
8. Preflight Git state and directory collisions; journal moves and worktree creation, roll back failures, and support explicit init --recover. Root-repository scaffold-named files move with their repository.
9. Refuse tracked changes, ordinary untracked files, and unknown ignored files before moving anything; initialization never silently strands local work.
10. Require an explicit --state-stopped assertion before database migration; preserve WAL, SHM, and rollback journals for all supported SQLite suffixes.
11. Extract only ignored, untracked state; refuse tracked destination replacement and exclude generated paths from accidental Git staging.
12. Reject migration of repositories with existing linked worktrees before changing their Git metadata paths.
13. Reuse one idempotent repository-setup routine for initial main and later workspaces; journal generated links for safe init rollback.
14. Preserve complete per-repository extraction reports in separate arrays and report concrete destinations without assuming env path resolution.
15. Serialize workspace creation/cleanup, validate and repair every repository on retry, record readiness only after setup, and reserve workspaces during launch.
16. Run dependency preparation synchronously, retain error output, and propagate failure before readiness or server/session launch.
17. Use literal registry keys, validate rows and path delimiters, reject duplicates, and support empty results when removing or updating the sole entry.
18. Serialize registry writers with a portable lock and atomically replace complete records using same-directory temporary files.
19. Validate every source before creating a workspace; reject empty, symlinked, bare, linked-worktree, and non-repository sources instead of silently sharing them.
20. Resolve explicit/configured/cached-default/source bases to commits, make fetching explicit, and require --reuse-branch for existing branches instead of error-driven fallback.
21. Propagate session, publication, and targeted/bulk cleanup failures through exit status; preserve partial results rather than claim success.
22. Install a selected release/commit from HTTPS with HTTP failure handling, verify its two-file checksum manifest, stage both files, and replace under a lock with rollback.
23. Quote all Makefile paths, reject empty/root install destinations, and uninstall only known files without recursive directory deletion.
24. Copy configuration with private permissions by default, keep shared links opt-in, migrate exact legacy links safely, and preserve edited managed files during cleanup.
25. Give each workspace a separate retained data directory, migrate original databases into main's directory, export HAP_DATA_DIR to sessions, and require --shared-data to share mutable state. Applications must use the exported/configured path; databases are never blindly cloned live.
26. Make dependency execution and branch publication opt-in via --install and --publish, including retries on existing workspaces; ordinary open does neither.
27. Attach to existing/resumable Zellij sessions without deletion; wait for GUI editors, clear markers on return/failure, and offer explicit stale-marker unlock with live-owner checks.
28. Traverse files with NUL delimiters, retain whitespace/backslashes and all dotfiles, reject unsupported state line breaks/symlinks explicitly, and propagate discovery failures.
29. Use XDG_DATA_HOME consistently in runtime, the release installer, and Makefile defaults while retaining explicit destination overrides.
30. Validate supported editors, Bash/Git versions, and selected dependency tools before workspace changes; keep fzf interactive-only, remove column dependence, and ship a generic Bash layout without undeclared tools.
31. Add regression/lint targets and Linux/macOS CI, consolidate extraction and lifecycle helpers, remove dead state, and resolve all ShellCheck findings.
32. Rewrite documentation and CLI help around verified behavior, migration/recovery, explicit side effects, real Git/SQLite semantics, and application-owned path resolution.

Final integration follow-ups: reject registry symlinks/directories and propagate registry setup errors before reading or replacing state.
Init also refuses ignored state beneath excluded directories and unrepresentable registry paths before migration, so extraction cannot silently leave approved state behind.
Session identities now use canonical project/workspace paths rather than ambiguous alias concatenation; cleanup also checks legacy names across all registered aliases.
